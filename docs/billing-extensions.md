## 官方接口与政策边界

[API Fast mode 文档](https://developers.openai.com/api/docs/guides/fast-mode)说明，API **响应**的 `service_tier` 标识实际处理档位。应区分请求设置、日志记录与服务端确认；API 响应字段的含义不能自动转移给 Codex 的同名配置字段。

[API 价格页](https://developers.openai.com/api/docs/pricing)单列适用的地区附加费，以及调用次数、容器会话、存储量等工具计费单位。因此，只有文本 token 总量和模型名不足以计算这些费用，也不能由机器时区推断处理地区。

[Costs API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs)提供 API 组织费用，当前时间桶为一天，可按项目、用户、账单行、API key 或 API 来源分组；部分组合依组织与时间范围受限，结果含金额及币种并支持分页。它没有这里所需的本机会话关联键，也不是 ChatGPT/Codex credits 交易接口。产品若接入，应称为“官方报告的 API 费用”，保留来源范围和抓取时间；本项目不能据此宣称最终发票或某次 Codex 会话的精确账单。[Administration 文档](https://developers.openai.com/api/reference/administration/overview)要求 Admin API key，不能复用桌面 ChatGPT 登录或默认假定普通 API key 有权限。

本次没有请求账户或费用接口。Enterprise 合同价、未采集的跨设备用量及 credits 交易仍需各自的官方数据，不使用公开 USD 价与本机 tokens 补齐。

## 历史估值的最小设计

以下是条件满足后的设计建议，字段名均为草案，不是已发布接口。

1. **先保存价格证据。** 在现有 v1 价格文档之外，用独立清单保存完整卡、指纹、来源、抓取/复核时间、产品范围及有证据的 `effectiveFrom` / `effectiveTo`。复核时间、提交时间和用户切换自定义卡的时间都不是官方生效时间。API 与 credits 分别建区间；模型/别名与计算规则也随版本固定。未实际发布的中间修订不补造成历史版本。
2. **时间区间采用 UTC 半开区间。** 仅在同一产品、模型及适用范围内选择唯一覆盖事件时间的规则。冲突、空档和无法确认的促销结束时间保持未覆盖；禁止回退当前价格后仍标作历史价格。界面按本地日展示时保留所用时区，切换时区重新聚合。
3. **先做按事件时间的等值报告。** 独立结果建议使用 `event-time-rates` 标识，明确事件时间归属规则、覆盖范围、缺价 tokens、模式/上下文假设和累计区间的不确定性。它仍是本机用量等值；遇到跨费率边界且无法拆分的累计差值，单列未覆盖，不按比例猜分。
4. **先限定可重放范围。** 当前扫描从当天起向前八天确定历史边界，结合文件修改时间发现日志，主要支持当天及当前周观察；缓存不是连续多日的事件账本。首版使用明确时间范围与可用日志，完整月报另做发现、留存和性能设计。缺原日志时，不从日总额或周分钟金额倒推出历史请求。

缓存中的 `TokenCostAccumulator` 按模型累计 tokens、价格签名、金额及缺项；`weeklyTimeline` 保存分钟金额与覆盖信息。两者均缺少重建任意历史费率所需的逐事件维度。已有 `pricing` 元数据只记录当前及最近一次价格转换，详见[重定价规则](pricing.md#repricing-and-unknown-usage)。

## 存储、迁移与验证预算

| 阶段 | 建议预算与复杂度 | 迁移方式 |
| --- | --- | --- |
| 本次评估 | 运行时存储与重放增量为零 | 保持价格 schema v1、缓存 v4 和所有公开字段。 |
| 价格归档 | 当前整份卡为 12,511 字节；按每年 50 份同尺寸卡估算约 0.60 MiB/年，另加来源清单 | 独立版本目录；首期只归档已取得的资料，不回填未知历史。自定义价格保存在本机，不上传仓库。 |
| 按事件时间报告 | 时间成本至少一次所选日志重放；复用副本对齐还需评估内存。优先流式计算并保存有界聚合，暂不保存完整事件流 | 新建独立缓存文件和版本，保留旧 v4；按来源范围、时区、价格清单及算法签名失效。新缓存失效时仅重建新视图。 |
| 官方费用导入 | 按时间桶与维度组合增长；独立于本机事件数 | 新建按组织/项目与导入来源隔离的存储，重复导入幂等；按相同查询范围替换完整快照，避免重复累加和漏处理修正。 |

未来报告的初始容量测试可按 **10,000 个聚合项、每项 1 KiB** 估算约 **9.8 MiB** 序列化数据；这只是设计预算，不是实测或用户规模预测。聚合键至少区分日期、来源范围、模型、价格版本、上下文档与模式/假设；限制达到时必须明确失败或报告未覆盖，不能静默丢弃。若先保存每个事件，按 100,000 条、每条 0.5–1 KiB 就需约 49–98 MiB，且尚未计入索引与解码内存，因此本阶段不选择全量事件账本。

独立存储需要单独锁、原子替换和可中断重建；以源文件指纹及处理代次确认新结果，不与旧缓存假装构成跨文件原子事务。旧版应用可忽略新文件；回滚期间新增或修正的日志，在再次升级后按指纹重放。原日志已删除的部分保留覆盖缺口，不迁移成零费用。官方周观察、余额和账户基线不从新金额更新。

实施时至少拆成价格清单、独立计算/存储、CLI/MCP、可选 UI 四个验收批次。先测量冷扫、追加、无变化、重建及副本对齐，再确认磁盘和内存预算；使用现有 256 MiB 与多副本基准，不以本次估算代替性能结果。

## 契约与验收门槛

- 保留现有 `todayCost`、credits 估值及 `pricing.basis: "current-rates"` 的含义。历史报告和官方费用采用独立命令/结果对象；原命令默认输出不被新口径替换。
- 历史报告覆盖费率切换前后、恰好边界、空档/重叠、促销未知期限、夏令时、跨日、跨 home、副本/父子导入、累计修正及缺失日志。增量、重启和重建须与独立手算结果一致。
- 实际档位必须有可核对的服务端样例，分别保存 requested/recorded/confirmed 来源；缺实际值不能默认为已确认 Standard。地区及工具必须具有适用规则和计费单位，避免与已含工具 token 的金额重复计算。
- 官方费用单独显示组织/项目、查询区间、币种、更新时间、分页完整性和导入/读取失败。未知归属不并入本机日汇总；日桶不能按本机小时比例切分或与本机等值相加。
- 新视图失败、取消、损坏、磁盘写入失败或回滚均不能破坏旧缓存与周历史。运行时实现按[验证要求](verification.md)执行 `make verify`；扫描/缓存改动增加基准，UI 改动检查双主题图像。
