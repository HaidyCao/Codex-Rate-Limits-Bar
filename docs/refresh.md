# 数据时效与刷新恢复

菜单分别显示额度、官方 credits 余额、重置券和本机统计的更新时间。状态包括尚未更新、刷新中、已更新、部分成功、刷新失败、未返回数据和数据已过期。悬停可以查看最后尝试、最后成功、数据时间、错误和下次重试时间。

- 官方三项数据超过 5 分钟、本机统计超过 2 分钟未更新时标记过期。开始刷新或失败不会把旧数据标成新数据；失败和过期标记可以同时存在。
- 请求失败时保留同一账户的旧数据并弱化显示。额度或本机统计不可靠时暂停展示周金额推算；额度失败或过期时暂停预测。新响应明确缺少某一字段时显示不可用，不把缺失余额或重置券数解释为零。
- 只返回重置券总数而没有明细属于部分成功，总数仍可用。本机扫描部分成功时显示这次扫描的数据时间，保留上一次完整成功时间；扫描错误和价格覆盖问题仍分别展示。
- 每个数据源的错误只由它自己的结果更新。本机扫描成功不会清除官方接口失败，开始重试也不会提前清除错误。

正常间隔为官方 60 秒、本机 30 秒。连续失败按各自间隔翻倍，最多等待 10 分钟；官方首次整体失败等待 60 秒，本机等待 30 秒。官方接口还有可用字段时保持 60 秒间隔，单项缺失或重置券失败不会拖慢正常额度和余额的更新，其错误仍保留并继续重试。手动刷新和重建可立即重试。系统唤醒会刷新两类数据，网络从不可用恢复时立即刷新官方数据；断网期间继续扫描本机日志。菜单打开时仍会更新状态。

每类任务最多运行一个，期间的新请求合并为一次后续刷新，保留重建要求。官方任务总超时为 45 秒，本机为 180 秒；接口自身还有 12 秒超时，缓存锁等待最多 15 秒。超时后立即显示失败并取消工作，原任务退出后才释放运行位置。子进程先请求结束，0.5 秒内未退出则终止该子进程；网络请求、扫描循环和锁等待支持取消。操作系统底层文件读写若暂时无法响应取消，不会不断创建替代任务。

账户、认证来源或请求代次变化后，旧结果不会应用到当前界面。扫描提交缓存前再次核对账户；取消或账户不匹配会放弃该次内存和磁盘缓存更新。已确认账户的 token 正常轮换不触发账户切换，无法确认身份的文件凭据按内容变化使旧请求失效。由 app-server 管理、没有可读文件身份的账户只能在官方响应返回新上下文后识别变化；此类账户继续不建立可归属的周金额基线。

## CLI / MCP

`status` 和 `get_codex_status` 的 `refresh` 字段包含四项状态。`local-usage`、`reset-credits` 及其 MCP 对应结果包含 `freshness`。字段为：

| 字段 | 含义 |
| --- | --- |
| `status` | `idle` / `refreshing` / `success` / `partial` / `failed` / `unavailable` / `stale` |
| `lastAttemptAtIso` | 最近一次尝试开始时间 |
| `lastSuccessAtIso` | 最近一次成功时间；失败不会推进 |
| `dataAtIso` | 当前数据对应时间；保留旧数据时也保留旧时间 |
| `ageSeconds` / `isStale` | 返回快照时的数据年龄和过期标记 |
| `error` | 当前数据源未恢复的错误 |
| `nextRetryAtIso` | 应用运行期间的自动重试计划 |

这些字段为追加字段，旧字段保持兼容。CLI/MCP 每次调用独立读取，只记录这次调用的结果，不继承菜单栏进程的刷新历史、网络监控状态或重试计划。失败结果没有成功时间；顶层 `fetchedAtIso` 不能替代成功时间。菜单栏的刷新状态保存在运行中的内存，重启后从尚未更新开始。

## 验证

统一入口与产物见[回归验证](verification.md)。`make verify` 默认使用隔离数据，真实账户检查需显式运行 `make verify-live`。

`make test` 覆盖状态独立性、时间推进、退避上限、手动重试、请求合并、账户切换、迟到响应、超时、取消及缓存事务。`make verify-local-usage` 使用隔离目录和假服务核对 CLI/MCP 成功、部分成功、字段缺失、错误、超时子进程清理和恢复；不会切换真实账户、断开系统网络或修改用户日志。

涉及 AppKit 生命周期的变更还需人工检查以下步骤，自动测试不能替代真实系统事件：

1. 打开菜单，检查浅色/深色外观下四项状态及时间完整可读；保持菜单打开时刷新时间仍推进。
2. 在有成功数据后断网，确认本机统计继续更新、失败提示不会消失；超过时限后旧数据弱化，周金额和预测暂停。
3. 恢复连接，确认自动更新；连续点击刷新/重建，确认界面可操作且请求不会持续堆积。
4. 刷新过程中让系统睡眠再唤醒，确认状态能恢复；唤醒时断网，再恢复网络，也应恢复更新。
5. 用测试账户切换登录，确认旧账户数据被清除，迟到结果不覆盖新账户；正常 token 轮换不清空本账户历史。
