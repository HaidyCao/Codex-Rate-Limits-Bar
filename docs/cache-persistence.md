# 本机缓存保存与恢复

本机扫描结果新增可选 `persistence` 字段，菜单、CLI `local-usage` / `status` 和 MCP 共享同一份状态。

| `status` | 含义 |
| --- | --- |
| `saved` | 本次结果已写入磁盘，或仍与已保存的缓存一致 |
| `pending` | 本次写入失败；结果保留在内存，后续刷新会重试，`error` 提供具体原因 |
| `disabled` | 当前未使用磁盘缓存，例如指定 `CODEX_SESSIONS_DIR` 的独立日志扫描 |

旧版本快照或没有完成扫描的失败结果可以没有该字段，不能据此推断保存成功。

## 展示与重试

持久化、扫描完整性、价格覆盖和数据时效各自表达不同状态。读取完整但保存失败时，tokens、金额和数据时间仍有效，`diagnostics.status` 保持 `complete`，`freshness` 保持成功。菜单显示橙色“缓存待保存”，悬停和错误详情说明重试及失败原因。若同时存在日志读取错误，两类错误都会保留；保存恢复不会清除读取错误。

写入失败后保留待保存标记；每次后续扫描完成账户和取消校验后，都会再次尝试保存，即使没有新日志、价格变化或额度样本。保存成功后才清除错误。无变化且已保存的扫描不会重复写文件。缓存文件被删除时也会从有效内存状态恢复。

重试仍使用原有进程锁、文件锁和原子替换。无法取得锁时仍按扫描失败处理，不绕过互斥写入。取消或账户校验失败的扫描会恢复之前的内存缓存及待保存状态，不提交当次结果。

## 历史与兼容

磁盘缓存继续使用 v4，文件格式、定价版本和解析版本不变，无需全量重扫。保存状态属于运行时快照，不写入缓存文档。

目标路径被占用、文件损坏或版本不受支持时，仍保留当前进程里已验证的缓存；没有内存缓存的进程会重新扫描。另一进程写入有效缓存时，采用新磁盘文件游标，仅在来源、账户、窗口和周观察基线全部匹配时合并未保存的观察样本；相同时间以磁盘样本为准，继续应用间隔、额度回退和保留时限规则。不同基线的历史不会混合。

保存失败期间退出进程，尚未落盘的额度样本可能丢失；会话日志可用于重算 tokens，但无法重建未保存的官方额度读数。应用会在进程存活期间持续重试，不承诺磁盘故障期间的跨重启保存。

## 验证

`CachePersistenceTests` 使用临时目录阻止原子替换，验证无变化重试、追加后恢复、旧文件保留、周基线和样本、并发进程、账户隔离、取消、删除/损坏、禁用缓存及旧快照兼容。CLI/MCP 使用隔离 home 重现写入失败和恢复；AppKit 增加“扫描完整但未保存”和“扫描不完整且未保存”两种场景，并检查状态行宽度。

运行 `make verify` 和 `make benchmark`；界面图片及性能产物见[回归验证](verification.md)。
